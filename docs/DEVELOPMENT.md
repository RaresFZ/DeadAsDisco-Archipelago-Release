# Development guide

## Layout

| Path | What |
|---|---|
| `archipelago/apworld/dead_as_disco/` | The Archipelago world: `catalog.json` (frozen content/ID map: 1164 candidate locations plus items), `options.py` (docstrings become the YAML comments), `world.py`, `configuration.py` |
| `archipelago/Dead as Disco.yaml` | Player template, generated by `tools/make-template.py` (do not hand-edit) |
| `archipelago/client/` | Self-contained Archipelago client: websocket (`apnet.py`), SQLite ledger, item/check dispatch, DeathLink, save decoder |
| `archipelago/dadap/` | The Windows app: GUI/CLI, reversible save swap (`session.py`), UE4SS staging (`core.py`), per-session binding (`binding.py`), `play.py` |
| `archipelago/game-mod/` | UE4SS Lua mod "APBridge" that runs inside the game (see its README) |
| `archipelago/data/` | Data the build and tests read: evidence snapshots pinned by the release certificate (`evidence/`), live-observed location ids, the save-variable schema |
| `archipelago/tests/` | Python tests |
| `tools/` | Dev setup, release builder, YAML generator, audit, local server, Lua fixtures, JS reference save decoder |
| `docs/FINAL_AUDIT.md` | Generated disposition of every candidate record (IMPLEMENTED / EXCLUDED_BY_DESIGN / BLOCKED) |

## Setup (from a fresh clone)

Requirements: Python 3.12+, git, Node.js 20+ (for one catalog check and the decoder parity tests), Windows (the app is Windows-only; the
tests that exercise it use fakes).

```
python tools/setup-dev.py             # creates .venv, installs packages, clones Archipelago 0.6.8 into artifacts/references/
python tools/setup-dev.py --release   # also downloads the pinned UE4SS archive (SHA-256 verified) needed by make-release.py
```

Everything it creates is git-ignored. Then (use `.venv\Scripts\python.exe` as `python`):

```
python tools/ap-slice-dev.py Tests                   # Python tests (skipped without private saves)
python tools/run-lua-tests.py                        # Lua fixtures (embedded Lua 5.4 via lupa; DAD_LUA = external interpreter)
node tools/test-ap-catalog.mjs                       # catalog predicates vs the save-variable schema
python tools/ap-slice-dev.py Generate --run mytest   # real Archipelago generation with the template YAML
python tools/make-template.py                        # regenerate archipelago/Dead as Disco.yaml
python tools/audit-release.py                        # regenerate docs/FINAL_AUDIT.md
python tools/make-release.py --version X.Y.Z         # artifacts/ap-release/DeadAsDiscoAP-X.Y.Z-windows.zip
```

To use another Archipelago checkout set `DAD_AP_ROOT`. Keep the working tree LF (`.gitattributes` enforces it): the release certificate
pins file hashes.

Some tests need real game saves and are skipped when none are present (9 skips on a fresh clone; that is normal): the decoder parity
tests read `artifacts/private-saves/{a,b}/SaveGames`, and the play-flow tests read a brand-new tutorial profile from `DAD_FRESH_SAVE`
(default `artifacts/private-saves/fresh/Saved`). Never commit saves.

## Releasing

There are two versions. The **release version** (`--version`) names the app package and the GitHub release. The **world version**
(`world_version` in `archipelago/apworld/dead_as_disco/catalog.json`) is carried by the apworld, the YAML and every generated
multiworld, and is part of the content hash the client checks. **Only bump the world version when multiworlds generated before the
change must stop working** (new/removed items or checks, option changes); a fix to the app, the client or the mod ships as a new
release of the same world, so players mid-multiworld can just update.

1. If the world changed: bump `world_version`, run `make-template.py` and `audit-release.py`.
2. `make-release.py --version X.Y.Z`; attach the zip to a GitHub release (notes in `docs/release-notes/X.Y.Z.md`). The zip contains
   the app, the mod files, the pinned UE4SS archive, the YAML, the apworld, the README and the audit, plus a certificate
   (`capabilities.json`, with both versions) pinning source hashes. The app shows the release version in its title bar.

## How it works (short)

- UE4SS is injected through a proxy `dwmapi.dll` at game start, only while a session runs. The app swaps in a separate profile
  for the Archipelago game and restores the player's saves afterwards (park by same-volume rename, full backup, hash manifests,
  idempotent recovery).
- Locations are read from the game's save variables (the client decodes the profile save); skill-node purchases are intercepted
  in-game so the vanilla reward is withheld. Items are granted natively and, for skills, equipped.
- Entitlements are published from the ledger *before* launch; otherwise the mod would remove received skills at startup.
- Traps and Fan Packs use at-most-once intent/ack files between client and mod.

Design facts worth knowing before changing the mod:

- Native `RemoveOwnedUpgrade` re-grants other powers; skills are removed through the reflected set plus a native unequip, powers are
  gated through their slot/applied effect (and a `CanActivateBossAbilityAtSlot` hook).
- Half Heart and DeathLink use `GE_Damage_SetByCaller` (hit cap 5 HP, same-frame hits are ignored, so lethal requests continue across
  ticks). The healing effect default object is unusable.
- The shipping exe relaunches itself under a new pid, so liveness is "any Pagoda process". The game starts Steam.

## Known gap for contributors

`catalog.json` was produced from an extraction of the game's data (asset identifiers, save-variable tags) by tooling that is **not**
part of this repository. You can still fix or extend records by editing the file and running the tests, but adding content that needs
fresh extraction from the game is not reproducible from a clone yet. The file format and how to edit it are described in
[CATALOG.md](CATALOG.md).

## Status and roadmap

Verified in live play: skill-node purchases as checks, AP skill grants and auto-equip, mission access, powers gated until delivered,
Half Heart and Silence, DeathLink both ways, challenges, persistence.

Not yet verified live:
1. **Fan Packs** (`credits.lua`, `AddCredits`): run in a protected test mode. After one run confirms fans rise by exactly the pack
   amount, remove `fan-packs` from `EXPERIMENTAL` and set it in `VALIDATED` (`archipelago/dadap/capabilities.py`), update
   `MECHANISM_EVIDENCE` in `tools/audit-release.py`, rebuild.
2. Pickup-based memorabilia checks, the Dex/Prophet/Dahlia access items, Silence cleanup on death/transition, low-health Half Heart,
   the story victory goal, and a multi-hour session.

Ideas, roughly in order:
- **No leaving the game after the tutorial.** Today the tutorial runs vanilla because the mod loads only at process start and its
  per-session config is built from the profile's first save. Options: (A) detect the saved tutorial, wait until the save file is
  quiet, close the game and relaunch with the mod automatically; (B) an "enrollment" mode where the mod runs from the first launch and
  binds on the first autosave (larger change); (C) stop requiring Steam to be closed once the Cloud setting can be read reliably.
- Fan Tax trap (negative `AddCredits`), heal/fever filler, a check-density slider, Universal Tracker support, an Archipelago Launcher component.
- Not possible or rejected: stamina trap (no stamina resource), cosmetic item shuffle (conflicts with purchase checks).

## When the game updates

The app only runs on the executables listed in `archipelago/dadap/pins.py` (`EXE_SHA256`, plus older builds in `PREVIOUS_BUILDS`); a
different one is refused. After a Steam update (the hash and build id are in `steamapps\appmanifest_3404260.acf`):

1. Check what changed. Extract the new build with the same offline tooling that produced the catalog (see the known gap above), compare
   the archived `.ini` files, localization, string tables and the item/location assets byte for byte, and note whether tags,
   save-variable names or class names moved. `archipelago/data/evidence/build-25772865-static-diff.json` is an example.
2. If the data is unchanged the catalog and the world version stay as they are. If it changed, update `catalog.json` and bump the world version.
3. Add the new hash to `pins.py` (`EXE_SHA256`; move the old one to `PREVIOUS_BUILDS`) and update `BUILD`.
4. Run the whole app against the new build once with a test profile (PLAY, play for a few minutes in the hub and a mission, check the
   console for `STATE ready` and no "bridge stopped itself") before publishing. UE4SS locates engine functions by signature, so a
   rebuilt executable can break it even when no game data changed.
## Safety when testing live

Never experiment on your real save. Use the app's profile mechanism (a dedicated profile per multiworld), keep Steam Cloud off, close
Steam before sessions, and keep the backups the app writes until you are sure a run was clean.
