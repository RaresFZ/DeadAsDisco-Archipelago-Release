# Dead as Disco Archipelago 0.6.5

Play **Dead as Disco** as an [Archipelago](https://archipelago.gg) multiworld randomizer, alone or with friends (and with any other
Archipelago game). Download **`DeadAsDiscoAP-0.6.5-windows.zip`** below, extract it and follow the `README.md` inside. No Python and no
Archipelago install are needed to *play*; only the person who generates the multiworld needs Archipelago.

> The "Source code" archives GitHub adds to this page are the repository, not the player package. Players want the `DeadAsDiscoAP-0.6.5-windows.zip`.

**Needs:** Windows 10/11, Dead as Disco on Steam at build **25902913** (the Halloween update, the current one), **25772865** or **25647873** (the app refuses other builds), Archipelago **0.6.8** for hosting.

## What the randomizer does

- **The skill tree is an Archipelago shop.** Buying a node costs fans as usual and sends a *check*; the node's vanilla reward is
  withheld. Your own skills arrive when the multiworld sends them and are equipped automatically.
- **Idol powers are shuffled.** Beating an Idol sends a check; its power arrives from the multiworld. A power you have not received
  cannot be equipped or used.
- **Missions are locked behind Access items.** You start with one mission of your choice (Hemlock by default); the other four open when
  their Access item arrives.
- **Everything you do can be a check**, and everything you receive can come from anyone's world. Filler, traps and DeathLink included.

## Checks (locations)

1164 candidate records exist; **1103 can be checks**, 11 are free at New Game and cannot be, and 50 song-related records are blocked.
A default seed has roughly **500 checks**; the options below scale that down or up (up to 1103 with songs).

| Category | Max | What counts |
|---|---|---|
| Story missions | 5 | Beating each Idol's mission (Hemlock, Arora, Dex, Prophet, Dahlia) |
| Star ratings | 530 | Reaching 1-5 stars on missions (you choose which thresholds) |
| Difficulty completions | 164 | Beating a mission on exact Easy / Normal / Hard / Very Hard |
| Challenges | 65 | Completing song challenges |
| Memorabilia | 148 | Collectibles; most count the moment you **pick them up** (hub or level), the rest when bought |
| Skill and power nodes | 12 | Skill-tree nodes of active skills and the Idol power awards |
| Passive upgrade nodes | 29 | The 29 passive upgrade nodes |
| Cosmetic purchases | 55 | Clothing bought in the shop (the clothing itself stays vanilla) |
| Dance purchases | 20 | Dance moves bought |
| Quests | 12 | Character item quests turned in |
| Achievements and tutorial | 27 | The game's achievements and finishing the tutorial |
| Infinite Disco songs (opt-in) | 36 | Completing each shipped song, plus their star and difficulty milestones |

Each category has an on/off option, and the big ones also have a percentage option (keeps a seeded random share), so you can build a short
or a very long seed. Checks that cannot be earned with your other options are never generated (for example, no quest check if quests are off).

## Items

57 item types:

| Items | Count | Notes |
|---|---|---|
| Idol powers | 6 | Phantom Dance, Thunderstruck, Singularity, Fever Rush, Show Stopper, Bass Invader |
| Active skills | 9 | Heavy Kick, Windmill, Drumstick Toss, Backup Sticks, Rush Down, Super Singularity, Super Bass Invader, and the free starters Double Time and Let's Dance |
| Passive upgrades | 29 | Stalwart Heart, Disco Inferno, Life Support, Perfect Pitch, Event Horizon and the rest of the tree |
| Mission Access | 5 | One per Idol mission |
| Fan Packs | 5 | Fans for the skill-tree shop: **125 / 250 / 500 / 1,000 / 2,000** at the default pack size (weighted toward small and normal) |
| Traps | 2 | **Half Heart** (lose a little health, never lethal) and **Silence** (run, but no attacking, dodging or abilities for a few seconds) |
| Disco Hint | 1 | Only if you lower the Fan Pack percentage; off by default |

The three free starter skills (Double Time, Fever Rush, Let's Dance) are your start inventory. Skills, powers, upgrades and Access items are
real progression/useful items; Fan Packs are filler; traps replace part of the surplus filler and never replace progression.

## DeathLink

Optional (off by default). An incoming DeathLink drains your health in small hits and then the normal death screen appears, with the usual
Retry. Your own death sends one outgoing DeathLink. Amnesty (forgive the first N per session) and cooldown are options.

## Goals

`story` (beat all five Idol missions, default), `mission_count`, `challenges`, `memorabilia`, `five_star_story` (5 stars on every Idol
mission) or `story_and_challenges`, with a goal count where it applies.

## The player YAML

`Dead as Disco.yaml` is generated with Archipelago's own template generator, so it looks like every other game's: grouped sections
(**Goal and Missions**, **Shuffled Rewards**, **What Counts as a Check**, **Filler and Traps**, **DeathLink**), every option explained in
plain language with its choices and weights, and `requires:` pinning Archipelago 0.6.8 and this world version. Theme groups work in
`exclude_locations` / `priority_locations` (Memorabilia, Challenges, Quests, Cosmetic Purchases, Dance Purchases, Story Completions,
Achievements, Song Completions, Skill Nodes, Upgrade Nodes, Star Ratings, Difficulty Checks, ...) and `local_items` / `non_local_items`
(Idol Powers, Active Skills, Passive Upgrades, Mission Access, Traps, Filler).

## The app

`DeadAsDiscoAP.exe` is a one-window launcher: type the server, your slot name and the password, tick that Steam Cloud is off, press
**PLAY**. It sets itself up, creates a separate Archipelago profile for each multiworld (you play the short tutorial once), starts the
game with the mod, connects to the server, and shows an Archipelago-style console with received items, chat and `!hint` / `!help`.

**Your real saves are never played on.** They are moved aside for the session and put back with a hash check, with a full backup kept;
**Recover saves** fixes any interrupted session. Nothing stays installed in the game folder between sessions.

## Fixes in 0.6.5

- **A skill the multiworld already sent you is delivered again if the game loses it.** Two players hit the same stop: the game closed or the launcher window showed *"Unhandled exception in script ... Applied ownership lost; refuse save rollback"* and it came back on every launch, because the game's save no longer had a skill the app had already recorded as given. The app used to refuse to go on. Now, when neither the running game nor its save has a skill the multiworld sent you, the app gives it to you again and says so in the log. A skill that is missing from only one of the two (a save still loading, an autosave still pending) is simply waited for. If a skill vanishes a second time in the same game session it comes back the next time you press **Play** (the mod will not grant one item twice in a single game session). Players who were stuck only need to update and press **Play**. **Not known yet:** why the game lost the skill. The first player's log shows it happened in the same second as skill-tree purchases; the app now writes what the game and the save held at that moment to `sessions\<id>\runtime\ownership-repairs.jsonl`, so if it happens again that file tells us. Checked with offline tests, not in a live run.

- **When the app stops itself, the window now says why.** A client that had stopped itself on purpose showed "The Archipelago client refused this connection (wrong server, seed or password)" (and "Server: No answer") whatever the real reason, and repeated the same two hints every second for the rest of the session. It now shows the real reason once, in plain words, and the app exits cleanly instead of leaving the "Unhandled exception in script" window open.

- **The in-game mod no longer stops itself silently.** A player saw "The game bridge stopped itself (...main.lua:174: Runtime refused; mutation disabled)" while doing an Infinite Disco challenge, twice. That text is only the *follow-up* of an earlier stop; the earlier cause was lost because the support file was overwritten by it. Two conditions stopped the mod for the rest of the session without writing any reason: the game not running the mod's check for more than 15 seconds (for example during a long level load) and a check starting while the previous one was still running. Now the mod skips the overlapping check, and after a long pause it reports "not ready", checks the save's owner, skills and anchors again from scratch and carries on. Real safety failures still stop it, and the support file `sessions\<id>\runtime\ap-refusal.txt` now keeps the **first** cause at the top. **Likely, not confirmed:** a long pause while Infinite Disco loaded was the cause for that player; if it happens again send `ap-refusal.txt` and `core\UE4SS.log`. Checked with offline tests, not in a live run.
- **Fixes "BindingError('Selection differs across contexts')" on a profile that has been played for hours.** Before it starts the game, the app picks one reference variable per part of the save and checks that it is the same playthrough. It took the alphabetically first variable of each context and gave up when two contexts of the same part no longer agreed, which happens once a long-played save has a variable in one context that the others lack. A player hit it after 4-5 hours, and the profile could not start any more. The app now picks the first variable that every context of that part has (the same one as before whenever the old rule worked). If no variable is shared the message says so. Tested with offline fixtures that reproduce the old error; not tried on a real long-played save.

- **"Access denied" is explained, and its location is recorded.** One player's launcher stopped with `PermissionError(13, 'Acces refuse')` while starting the tutorial, and nothing said which file or what to do. The cause is **not known** (a folder held open by another program or a security tool is the usual reason, and running as administrator does not help); it happened once and then went away. The launcher now says in plain words what to try, shows the file involved, and writes where the error happened into `launcher-log.txt` for any unexpected error.
- **The app's messages no longer sound like a support promise.** The launcher's help text and a few error explanations said things like "send me" or "ask me and I will add it". They now say you can ask in the Dead As Disco channel of the Archipelago Discord server and that replies may be slow, because the project is not actively maintained at the moment (see the README's *Project status*).

- **The window now tells you when the Archipelago connection program dies.** If that part of the app crashed in the middle of a game session, nothing said so and you kept playing without checks or items. The window now shows "The Archipelago connection stopped" with the last line of the client's log, and the whole error is kept in `sessions\<id>\runtime\client.log`. Any crash of that program also ends cleanly now, without the "Unhandled exception in script" window. Whether this explains a player's "checks stopped completing after hours" is **not known**.
- **If preparing the saves fails half-way, they are put back at once.** A full disk or a file held open by an antivirus while the app swapped in the Archipelago profile left everything in place for the Recover button. The app now puts the saves back by itself and only asks you to press **Recover saves** if that fails too.
- **The mod no longer removes a skill because it could not read a file for a moment.** To keep skills you have not received away from you, the mod removes any skill that is not on the list of received skills the app writes next to the game. If that list could not be opened at that very moment (the app replacing it, an antivirus scan), the mod read it as an empty list and removed every skill it was withholding. Now an unreadable list means "wait", never "remove". This may be one of the causes of the *"Applied ownership lost"* reports; that is **not confirmed**. A hook that cannot read the launch file for a moment also skips instead of stopping the mod.
- **Old session files are cleaned up.** Every session left about 35-40 MB behind (a backup of your saves, a copy of the mod loader, an older copy of the profile): 31 sessions were over 1 GB. After a session that ended cleanly, the app now deletes the oldest finished ones and keeps the 5 newest session folders, the 4 newest backups plus the very first one, and the 2 newest older copies of each profile. It never touches an open or unfinished session, a session that kept partial saves, or anything it does not recognise.
- **Only one launcher can run at a time.** A second window (or `DeadAsDiscoAP.exe recover` while the launcher is open) could move the first one's parked saves around. It now tells you the launcher is already open.
- **Recover also finishes an interrupted save move.** If the PC died in the middle of moving the Archipelago saves into the profile, the profile could end up without its saves folder and look new. Recover now completes the move.
- **A save the game is still writing no longer stops the app.** A half-written or damaged save is now simply read again a second later instead of crashing or stopping the connection program.
- **archipelago.gg is only contacted over the encrypted connection** (no fall back to a plain one, which would have sent the password unencrypted). Small fixes: the settings file is written safely and the launcher's local page ignores a malformed request instead of hanging.
- **The room password is no longer on the connection program's command line.** It is handed over through the environment instead, so other programs on the PC can no longer read it from the process list.

## Fix in 0.6.4

- **Supports the new Dead as Disco update (Steam build 25902913, the Halloween update).** I compared the new game files with the previous build: the update only adds content (a pumpkin-head hair cosmetic, a pumpkin trinket, a new Dancer challenge and Halloween arena changes) and rewords two skill descriptions. Nothing the randomizer uses was removed or renamed, and every in-game function the mod hooks is still in the game. The new content is not part of the multiworld yet (it is simply ignored), so **existing multiworlds keep working** (the world is still 0.5.5). The app accepts the three game builds 25902913, 25772865 and 25647873. Tested live on the new build since: the game starts with the mod and the app reads its saves. If the game does not start with the mod, or the app says it cannot read a save, tell me in the Dead As Disco channel of the Archipelago Discord.

- **Clear message when the game opens the wrong save.** If the game loads a save other than the Archipelago one (usually a New Game or the tutorial started again by mistake), the launcher now says so in plain words and what to do: in the game choose **Continue** on the save from your first tutorial. The launcher also reminds you to press Continue as soon as the game starts.

- **The in-game mod no longer stops itself with "Ambiguous node playthrough".** Sessions ended with "The game bridge stopped itself (...skill-locations.lua: Ambiguous node playthrough)", for some players every time they upgraded a skill or went to the hub. The mod's skill and power hooks run when the game equips or buys things, which also happens at moments when the game's save cannot be read yet (loading a level, menus). Instead of waiting, the mod treated that as an error and stopped for the rest of the session (your saves were never at risk). Now those moments are skipped, unreceived skills and powers stay locked as before, a skill you buy at such a moment still counts as a check, and the mod keeps running. Skipped moments are written to the session's `node-journal.jsonl` (`node-hook-skipped`) so they can be looked at. Real safety failures still stop it.

## What is new since 0.5.10

- **A new launcher window, made from the Dead as Disco design.** Yellow and violet, big PLAY, the launch checklist (Steam Cloud, Game files, Saves, Server, Slot), live counters for items, checks and hints, a colour-coded log with filters, and a chat box. It has its own title bar (minimize, maximize, close; drag it by the title) and its own disco-ball icon in the taskbar. It runs in a window made with Microsoft WebView2 (installed with Edge, present on Windows 11 and most Windows 10 PCs). If that is missing the app opens an Edge or Chrome app window instead, and if that is not possible either, the previous window. The window talks to the app only through a local connection on your own PC (127.0.0.1) protected by a secret code made at every start, so no website or other program can press Play. Closing the window while a game session runs does not end the session: the app keeps running until the game is closed and your saves are back.

- **Errors explained in simple words.** When something fails, the launcher says what it means, gives the steps to fix it yourself, and if that is not enough tells you to ping **@the_twelvez** in the Dead As Disco channel of the Archipelago Discord server with a screenshot and a description of what happened. The technical message is still shown in the journal, a **Copy details** button puts everything needed in your clipboard, and the whole journal is saved in `%LOCALAPPDATA%\DeadAsDiscoAP\launcher-log.txt`.

- **Much less stutter on slower PCs.** The mod ran a full check of the game every 2 seconds on the game thread. On a mid-range PC a report showed a short freeze (about 55-70 ms) with every check, plus a half-second freeze (about 400 ms) roughly every 20 seconds while it looked up which of your received items the game could take. Now:
  - The half-second freeze is gone: only items you have received and do not own yet are looked up, a few at a time.
  - When nothing is happening the mod does a full check every 4 seconds instead of every 2, and re-reads the whole progression only every third time. It still looks at its control files every second, so a received item, trap or DeathLink is picked up within about a second, and while anything is in flight it checks every 2 seconds.
  - The mod writes its timing log less often, and the app no longer decodes your save file every 3 seconds: it decodes only when the game has written it (or a skill node was taken), so it uses less CPU and a check shows up sooner.
  - Every check except skill-tree nodes is read from the game's own save file, so it appears when the game autosaves, which the mod cannot speed up.

  Measured only on one player's log and offline tests, not yet in a new live run: if you still see stutter, send `sessions\<id>\runtime\ap-evidence.jsonl`.

- **Fixes the stop after the first tutorial ("This profile has no save yet. Run 'newprofile'").** If the game was closed before it had written both of its tutorial save files (for example with Alt+F4 or Task Manager instead of the game's menu), the app stopped with a message about a command the app does not have. Now pressing PLAY again simply plays the tutorial again on that same Archipelago profile (your real saves are never involved). **Check install** also reports an incomplete tutorial save.

- Nothing changes for existing multiworlds: the `dead_as_disco.apworld` and YAML in this zip are still version 0.5.5.

## Earlier changes since 0.5.6 (app and mod fixes)
- **Fixes "CERTIFICATE_VERIFY_FAILED ... certificate has expired" when connecting to archipelago.gg.** Some PCs have an out-of-date Windows certificate store and rejected the server's valid certificate. The app now falls back to its own bundled trusted roots (still checking the server and its name), tries the secure address first for archipelago.gg, and tells you to check the PC's date and time if the certificate is still rejected.

- **Fixes "ERROR: SaveError('Unsupported save header')" after the game update.** The update stamps every save it writes with a new engine version, and the app only accepted the old one, so it could not read the profile after the tutorial. Saves written by both game builds are read now (checked against real saves from both).

- **Supports the new Dead as Disco update (Steam build 25772865).** The update changed combat and boss behaviour and re-cooked many
  levels; the game's configuration, text, item and location definitions are byte-identical, so no multiworld is affected. Builds
  25772865 and 25647873 are both accepted.
- **A slow moment no longer ends the session.** A single slow moment (such as loading the hub on a slower PC) used to end the session
  with "The game bridge stopped itself (callback-time-budget)". The bridge now backs off and only stops on a real error or a stall of
  several seconds, and the message says exactly which it was and where to find the details file.
- **The window now finds Dead as Disco wherever Steam is installed** (for example `F:\Steam`) and asks for the game folder if it still
  cannot find it, instead of crashing with "Dead as Disco install not found".
- Everything from 0.5.6 stays: no lock-out after closing the game at the wrong moment, and errors show up immediately.
- **Multiworlds generated with 0.5.5 keep working**: the `dead_as_disco.apworld` and YAML inside this zip are still version 0.5.5. Only
  the app and the mod changed: replace the app folder and press PLAY. Progress lives in `%LOCALAPPDATA%\DeadAsDiscoAP` and is not touched.

## Known limits

- **Fan Packs are experimental.** They run in a protected test mode until one live run confirms the exact fan amounts.
- **Not yet confirmed in live play:** memorabilia pickup checks, the Dex / Prophet / Dahlia Access items individually, Silence cleanup on
  death or level transition, Half Heart at very low health, the story victory goal, and multi-hour sessions.
- **After the tutorial you must quit the game and close Steam once** so the Archipelago game can start; an automatic restart is planned.
- Steam Cloud must be off for the game while you play, and the a supported game build is required.
- **Not possible:** a stamina trap (the game has no stamina), shuffling the cosmetic/dance rewards themselves (only their purchases are checks).
  50 song-related records are not checks because their song data cannot be tied to a visible, unlockable song.
- Multiworlds generated with an older, pre-release version are not compatible; generate a new one.
